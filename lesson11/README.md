# vuln_management_lab — заняття №11

Скрипти до заняття «Управління вразливостями: NVD, KEV, EPSS, OSV»
курсу **Кібербезпека з нуля**.

Усі скрипти:
- нічого не змінюють у системі (read-only, лише HTTP-запити та читання інвентаря);
- працюють на Windows / macOS / Linux;
- не потребують ключа API, окрім NVD (та й там ключ необов'язковий);
- мають детальні коментарі українською — код призначений для читання, а не лише для запуску.

## Швидкий старт

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp env.example .env          # і впишіть свій NVD_API_KEY (необов'язково)

python 01_nvd_basic.py nginx
python 02_nvd_to_csv.py nginx --max 500
python 03_kev_epss.py CVE-2021-44228 CVE-2024-3400
python 04_inventory.py                              # -> inventory.json
python 05_osv_scan.py requirements.txt
python 06_risk_report.py --limit 10 --per-app 5     # -> risk_report.csv
```

## Скрипти

| Файл | Що робить |

| `01_nvd_basic.py` | найпростіший запит до NVD API 2.0: пошук CVE за ключовим словом |
| `02_nvd_to_csv.py` | пагінація по всіх сторінках NVD і вивантаження результату у CSV |
| `03_kev_epss.py` | пріоритезація P1–P4 за CISA KEV (факт атак) та EPSS (прогноз) |
| `04_inventory.py` | інвентаризація встановленого ПЗ з версіями у JSON (без `shell=True`) |
| `05_osv_scan.py` | перевірка Python-залежностей через OSV.dev (supply chain) |
| `06_risk_report.py` | повний конвеєр: інвентар → NVD → KEV → EPSS → `risk_report.csv` |
| `07_homework_template.py` | шаблон домашнього завдання з TODO |

## API, які використовуються

| Джерело | Ключ | Ліміт |
|---|---|---|
| NVD 2.0 | необов'язковий, безкоштовний | без ключа — 5 запитів / 30 с (пауза 6 с), з ключем — 50 / 30 с |
| CISA KEV | не потрібен | JSON-фід цілком, без ліміту |
| EPSS (FIRST) | не потрібен | без жорсткого ліміту |
| OSV.dev | не потрібен | до 1000 пакетів одним POST |

Ключ NVD: https://nvd.nist.gov/developers/request-an-api-key

## Важливо про CVSS у 2026 році

З 15 квітня 2026 року NIST більше не додає оцінку CVSS до кожної CVE:
пріоритет мають записи з каталогу CISA KEV та критичне ПЗ уряду США, решта
отримує статус «Not Scheduled». Тому порожній `score` у результатах — це не
помилка скрипта. Саме через це в уроці ми переходимо від CVSS до зв'язки
**KEV + EPSS**: факт експлуатації плюс ймовірність атаки дають реальний
пріоритет патчингу, а не теоретичну шкоду.

## Точність результатів

Пошук у NVD за ключовим словом дає багато хибних збігів (запит «Chrome»
знайде і сторонні продукти зі словом Chrome в описі). Промислові сканери
працюють через CPE — точний ідентифікатор продукту й версії. Звіти цих
скриптів — навчальна оцінка, а не результат аудиту.
